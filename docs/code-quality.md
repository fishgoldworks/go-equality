# Code quality

This library follows the Engineering Playbook's [JavaScript conventions](../../engineering-playbook/standards/javascript/conventions.md) and [code quality guidance](../../engineering-playbook/guidance/javascript/code-quality.md), with application-owned ESLint and Prettier configuration. The published library has no runtime dependencies.

## Tool configuration

The local [eslint.config.mjs](../eslint.config.mjs) composes the official `@eslint/js` recommended rules, `typescript-eslint` type-checked rules, scoped `globals`, import/dependency checks, and focused-test detection. [.prettierrc.json](../.prettierrc.json) owns the shared formatting values. All required npm tools are explicit, exactly pinned development dependencies, with the npm-managed lockfile recording their resolved versions and integrity. No private configuration package, vendored archive or playbook checkout is required for `npm ci`.

The upstream versions preserve the compatible toolchain used before the private configuration was removed, with versions owned by the [development manifest](../package.json) and [lockfile](../package-lock.json). Review effective correctness rules, environment scopes, compiler projects and deliberate exceptions when updating tools. Keep production imports separate from development-only files and dependencies, retain type-aware promise and unsafe-operation checks, and reject unused disable comments. The Acorn bundler and Python Playwright browser harness remain library-specific tools; their existing checks and browser matrix are preserved.

Manifest ordering and common npm commands follow [the shared library command catalogue](../../../Instructions/library-commands.md). Apply consumer metadata changes through [package-layout.js](../scripts/package-layout.js), preserving nested export conditions and fallback order. Optional `os` and `cpu` extension fields follow the standard manifest fields, in that order.

## Tools and checks

Run `npm ci` with Node 22.18+ within Node 22, or Node 24+. This development-tool requirement is separate from the published CommonJS runtime minimum of Node 8.0.0. Default and named ES module imports, including emitted TypeScript consumers, are checked on Node 12.20.0, 14.13.0, 16.0.0 and modern Node. Runtime source and bundles use ES2017 syntax; optional BigInt, shared-memory and newer RegExp capabilities must not prevent ordinary comparisons when absent. ESLint, Prettier and typescript-eslint versions are pinned in the [development manifest](../package.json) and [lockfile](../package-lock.json). TypeScript remains 5.8.3 to preserve the declaration compatibility check.

[eslint.config.mjs](../eslint.config.mjs) selects CommonJS/Node for runtime code, Node scripts and tests; ESM/Node for configuration; browser globals only for the real-browser suite. Type-aware linting checks declarations and compile-only tests using their TypeScript projects. The root [tsconfig.json](../tsconfig.json) covers the declaration entry point. The test project maps the package name to the canonical declaration for typed linting in the private checkout; isolated consumer checks remove that repository-only mapping and resolve the generated or installed package.

`npm run lint` fails on errors or warnings. `npm run format:check` checks all supported maintained files, including both documentation templates. Both run at the start of `npm run verify`, whose contributor checks run on Node 22 and 24. Select an exact Node 8.0.0 consumer executable with `npm run verify -- --node /path/to/node-8.0.0` or `GO_EQUALITY_NODE8`; verification fails if that required runtime is missing or has a different version. Local hooks are optional; branch protection must require CI checks to block merges. The CI configuration is committed; remote branch-protection settings must be configured separately.

Build, bundle, and documentation tests check the generated `package/`, `README.md` and `docs/API.md`. Generated package output, historical release records, dependency/cache output, IDE metadata, local playgrounds in `src/temp/` and the verbatim licence document are excluded from linting and formatting. Preserve the playground files for manual experimentation; Git and consumer builds exclude this directory. These exclusions must not expand to maintained source just to obtain a passing check. The `files` list in generated `package/package.json` excludes tooling and tests from npm. Package tests check the installed contents.

The release orchestrator in [verify.js](../scripts/verify.js) creates one candidate through `pack:package` and passes its tarball to the package checks; `verify:all` adds Chromium, Firefox and WebKit checks of the same archive. `npm run pack:package -- --destination artifacts` builds fresh output and records the tarball's SHA-256. Pass `--tarball` to `verify` or `verify:all` to rerun the complete gate against a retained candidate. Supplied `--tarball` paths are consumed without rebuilding or repacking, and a missing supplied file is an error. CI builds and packs on Node 22 and runs the complete standard gate again on Node 24 using that same archive. The development root is private. The build assembles one complete, ignored `package/` directory from canonical sources, declarations and metadata; only that directory is packed. Root pack/publish hooks reject wrong-directory operations. Type, artefact and constrained-memory gates install the same supplied archive even when local build output is absent.

`npm run test:release` protects candidate packing and reuse, missing-file failures and avoidance of recursive packing hooks. `npm run test:tooling` covers development-command input handling, child-process failures and consumer cleanup errors. Both are part of verification. The full modern runtime suite uses Node's built-in test runner; Node 8 runs focused installed-consumer regressions instead of trying to run contributor tooling.

## Package layout

Edit `src/*.js`, `index.js` and `index.d.ts` for runtime and declaration changes. Consumer metadata and the four public export routes are generated by [package-layout.js](../scripts/package-layout.js); contributor dependencies and hooks do not ship. The build copies consumer documentation and replaces the complete `package/` only after its format checks succeed. It leaves canonical inputs untouched. Failures before replacement preserve previous output; replacement failures restore it or report a retained backup. Once the new package is active, a backup-removal failure exits unsuccessfully but keeps that new package. The diagnostic identifies the active package and cleanup path and retains the original error. Any remaining backup may be incomplete, so post-replacement cleanup does not trigger rollback.

Use `npm run build` before standalone `test:types`, `test:artifacts` or `test:loaders`. The first two also accept `--tarball` to check an existing candidate. Install a local tarball with `npm install /path/to/go-equality-2.0.0.tgz`, or build and link `/path/to/go-equality/package`. Do not install/link the private repository root or use it as a Git dependency. After release approval, publish the exact verified tarball.

## Documentation style

Use New Zealand English in documentation and comments, for example behaviour, normalise, customiser and licence. Keep API identifiers, filenames, commands and third-party licence text unchanged. Explain unfamiliar terms where they first appear and prefer concrete descriptions of what the code does.

Use `// => result` for expected values and `// => throws ErrorType` for expected exceptions in examples. Keep plain `//` for explanations and type annotations. Align result comments across nearby blocks that show related alternatives or the same function, including across blank lines. Use a shared column for ES modules and CommonJS usage alternatives. Start at one-based column 32 and enlarge the group to the smallest even column allowing at least two spaces after its longest annotated code line. Keep unrelated API sections and unusually wide examples independent to avoid excessive padding.

## Deliberate exceptions

Library maintainers should review these exceptions when the related behaviour or test changes and remove any that are no longer needed. Unused disable comments are errors.

- README and API-reference example blocks with aligned trailing result comments use `<!-- prettier-ignore -->` immediately before the fence to preserve readable comment columns. Keep this exception scoped to those blocks; executable documentation checks still validate their results.
- `eqeqeq`: three explained statements in `src/compare.js`, `src/ComparisonContext.js` and the independent test oracle implement deliberate loose primitive equality. Replacing these operators would change the public contract. Source, oracle, artefact and real-browser tests protect the behaviour.
- `@typescript-eslint/no-unsafe-call` and `require-await`: individual negative declaration assertions intentionally call missing members, reject narrowing or pass an asynchronous callback. Their `@ts-expect-error` directives require the compiler to reject those cases; the surrounding file retains typed lint.
- `@typescript-eslint/no-require-imports`: one import-equals statement deliberately tests the CommonJS declaration contract, alongside the separate ES module fixture.

Build and consumer-check error handling must preserve both the original failure and any cleanup failures. Attempt each owned cleanup even if an earlier cleanup fails. A cleanup failure must also fail the command when the checks passed. Avoid throwing inside `finally`, which can hide the original error, and keep the build-recovery and consumer-cleanup tests.
